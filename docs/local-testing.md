# Local testing

These notes show a basic manual test flow for the Worker API.

## Start the worker

```bash
npm install
npm run dev
```

Wrangler usually starts the worker at:

```text
http://localhost:8787
```

## Health check

```bash
curl http://localhost:8787/health
```

Expected response:

```json
{
  "ok": true,
  "service": "wa-attribution-toolkit"
}
```

## Create a tracked link

```bash
curl -X POST http://localhost:8787/links \
  -H "content-type: application/json" \
  -d '{
    "target_url": "https://wa.me/5511999999999",
    "title": "Local test campaign",
    "campaign": "local_test"
  }'
```

The response should include a `tracked_url`.

## Track a click

Open the returned `tracked_url` in a browser or call `/track` directly:

```bash
curl -I "http://localhost:8787/track?target=https://wa.me/5511999999999&utm_source=local&utm_campaign=local_test"
```

Expected behavior:

- HTTP redirect response
- click stored in D1
- `click_id` added to the final target

## Register a lead

Use a `click_id` generated by `/track`.

```bash
curl -X POST http://localhost:8787/leads \
  -H "content-type: application/json" \
  -d '{
    "click_id": "replace-with-click-id",
    "name": "Local Test",
    "phone": "5511999999999",
    "metadata": {
      "source": "manual-test"
    }
  }'
```

Expected response:

```json
{
  "id": "lead-id",
  "click_id": "replace-with-click-id",
  "webhook": {
    "forwarded": false,
    "status": null
  }
}
```

## Check stats

```bash
curl http://localhost:8787/stats
```

If `ADMIN_TOKEN` is configured, send the matching authorization header.

## Notes

- Use fake phone numbers and fake campaign values in local tests.
- Do not paste production webhook URLs into public issues.
- Keep real customer data out of test payloads.
